## 协作方式

本计划将审查发现固定为 `P01` 至 `P10`。所有项目初始状态均为“待确认”，未经管理员明确同意，不修改对应业务代码。

每项按以下流程推进：

1. 说明现状、风险、修改方案、影响范围和验证方法。
2. 管理员决定“修改”“调整方案”或“跳过”。
3. 获准后单独实施并完成自动化测试、必要的页面验证与兼容性检查。
4. 在本文件记录实施结果、提交版本和遗留事项，再进入下一项。

## P01 移除管理员明文密码

**现状**：首次安装已将密码哈希保存到数据库，但仍会把原始管理员密码写入 `.env`，升级备份也可能继续复制该字段。

**目标**：数据库中的强密码哈希成为唯一长期凭据，不在环境文件、日志或备份中保存管理员原始密码。

**预计修改范围**：

- 首次安装不再写入 `AGMS_ADMIN_PASSWORD`。
- 程序启动或升级时识别并删除历史遗留字段，不改变当前数据库密码。
- 更新 `.env.example`、安装说明和相关测试。
- 检查日志、备份脚本及发布包，确认不会再次输出该值。

**验证标准**：

- SQLite 与 MySQL 首次安装后均能正常登录。
- `.env`、升级备份和应用日志中均不存在管理员明文密码。
- 已部署实例升级后仍使用原密码正常登录，且遗留字段被安全移除。
- 登录、修改密码、更新和回滚相关测试全部通过。

**实施结果（2026-07-29）**：

- 新安装只向数据库写入 PBKDF2-SHA256 密码哈希，不再生成 `AGMS_ADMIN_PASSWORD`。
- 旧部署若仍在 `.env` 中保存密码，会先完成数据库哈希迁移，再原子删除环境文件中的明文；数据库已有新密码时不会被旧环境密码覆盖。
- 取消环境密码及内置默认密码的日常登录兜底。仅对过去确实依赖旧默认密码的已安装数据库执行一次兼容迁移，并强制管理员登录后立即修改密码。
- 新创建的升级备份会主动剔除旧密码字段；现有本地 `.env` 已确认无该字段。
- 新增专项回归测试，完整后端测试共 76 项通过，前端生产构建、发布脚本语法和备份脱敏演练通过。
- 已完成本地真实登录验证：需要改密的账号无法进入其他后台页面，只能进入系统设置完成密码更新。

## P02 API Key 权限分离

**目标**：API Key 不再天然等同完整管理员权限；支持独立生成、撤销、轮换、权限范围和调用审计。

**初步范围**：设计只读、上传、元数据维护、系统管理等权限；兼容现有后台会话；为旧 Key 提供明确迁移策略。

**实施结果（2026-07-29）**：

- 保留管理员后台显示完整 API Key 的现有行为，并继续支持复制；Key 原值仍由受限权限的 `.env` 保存。
- 新增媒体库读取、图片上传、资料维护、永久删除、系统只读、系统设置、更新只读、执行更新和 API Key 管理共 9 项权限。
- 全选 9 项权限时具备完整系统控制能力；后台会明确显示高权限警告，旧 Key 升级时自动迁移为全部权限。
- 支持独立创建、修改名称与权限、设置有效期、立即撤销、全部重置，并记录最近调用时间和来源 IP。
- 支持单独刷新指定 Key；刷新后保留名称、权限和有效期，旧 Key 立即失效。
- Key 默认隐藏，可逐项显示或隐藏；双击密钥输入框可直接复制完整 Key。
- 普通设置权限不会返回完整 API Key；只有浏览器管理员会话或同时具备 API Key 管理权限的 Key 才能读取密钥列表。
- API 文档为每个受保护接口标注 `x-api-key-scopes`；权限不足返回 403，未知、过期或已撤销 Key 返回 401。
- 新增专项安全测试并完成真实页面操作验证；完整后端测试 83 项通过，前端生产构建通过。
- 2026-07-30 完成最终交互调整、刷新接口权限校验和文档更新，P02 正式标记完成。

## P03 首次安装保护

**目标**：使用一次性安装令牌和原子安装锁，防止未初始化服务被他人抢先设置，也防止两个安装请求互相覆盖。

**初步范围**：启动器生成临时令牌、安装页自动携带、服务端校验、安装过程加锁、提高管理员密码要求。

**实施结果（2026-07-30）**：

- 启动器只在未安装状态生成强随机临时令牌；程序只保存令牌摘要，原值仅通过首次安装地址交给管理员。
- 安装页从地址片段读取令牌后立即清理地址栏，请求通过 `X-Install-Token` 提交；无令牌或错误令牌使用相同的拒绝响应，并对来源 IP 限流。
- 临时令牌有效期为两小时，安装成功后立即销毁；服务重启会生成新令牌，旧令牌随即失效。
- 安装过程同时使用进程内锁和操作系统文件锁，重复或并发请求不能覆盖数据库、管理员账号或环境配置。
- 数据库使用“进行中”和“已完成”标记区分部分失败与完整安装；中途失败可以重试，不会把只有迁移表的空库误判为已安装。
- 管理员密码最低提高到 12 位，禁止与用户名相同及常见默认密码；会话签名密钥始终由服务端生成，不再接受网页输入。
- 安装接口不再向未授权请求暴露锁文件、数据库初始化细节或内部异常；服务日志只记录脱敏后的异常类型，避免数据库凭据进入日志。
- 已通过令牌、限流、并发锁、失败脱敏、弱密码和真实空 SQLite 数据库首次安装测试；完整后端回归、前端生产构建及安装脚本语法检查通过。

## P04 详情接口与分页

**目标**：作品和角色详情只返回基本资料及准确统计数，图片和角色列表使用独立分页接口，避免一次返回上千张图片。

**初步范围**：调整响应模型；补齐角色详情翻页或自动加载；保持前后台现有展示行为。

**实施结果（2026-07-30）**：

- 作品详情不再加载或返回全部角色、全部图片，只返回作品资料、封面、背景、`character_count` 和 `image_count`。
- 角色详情不再加载或返回全部图片，只返回角色资料、所属作品、头像和 `image_count`。
- 关联内容统一通过现有分页接口读取：角色使用 `/api/characters?work_id=...`，图片使用 `/api/images?work_id=...` 或 `/api/images?character_id=...`。
- 访客详情计数排除私有和 `hidden` 图片；管理员会话或具有 `library:read` 权限的 API Key 可以获得完整计数。
- 前台角色详情页由固定读取前 48 张改为每页 24 张，增加准确总数、页码切换、加载状态、空状态和路由切换重载。
- 前后台作品页及后台角色页继续使用现有分页，并可先用详情计数字段稳定显示总数。
- 网页 API 文档和运维调用说明已更新，明确详情响应不再嵌入完整关系集合，这是一次有意的接口契约调整。
- 新增访客/管理员计数、隐藏内容过滤、响应瘦身和关系分页专项测试；完整后端测试 100 项通过，前端生产构建通过。

## P05 批量上传事务与重复预检

**目标**：整批文件先完成校验，再统一创建任务；任何文件失败时不留下不可见的半成品任务。SHA256 使用批量查询。

**初步范围**：分阶段暂存、批量数据库查询、事务提交、失败清理、批量与并发测试。

**实施结果（2026-07-31）**：

- 服务端先校验整批文件的后缀、大小、可解码性、图片属性及作品/角色 ID，再开始创建任务；任一文件失败会清除本批已暂存文件。
- 每个文件只在服务端计算一次 SHA-256 和图片检查结果，并随任务保存；worker 不再重复执行同一轮解码检查。
- 同一批任务通过一次数据库事务统一写入，数据库提交失败时整批回滚并清除暂存文件，不再留下部分成功但前端不可见的任务。
- 重复预检改为分块批量查询，同时区分图库已有、上传队列已有和本批次内重复；前端跳过重复项时按文件位置处理，不会误删同名但内容不同的文件。
- worker 对同一 SHA-256 使用进程内互斥，数据库唯一索引负责跨进程最终兜底；并发冲突会复用已有图片，不覆盖元数据，也会清除竞争失败方生成的文件。
- 图片转码、衍生图生成或数据库写入失败时会清理本次生成的原图、HDR 预览图和缩略图；暂存写入失败也会删除可能存在的不完整文件。
- worker 启动异常不会撤销已经原子提交的任务，任务仍保持可见和可恢复；服务重启恢复、任务租约、重试与取消继续由 P06 处理。
- 新增 7 项专项测试，覆盖整批校验失败、无效关系、数据库失败、500 个 SHA 批量查询、队列重复预检、同哈希并发和衍生文件清理；完整后端 107 项测试、空 SQLite 安装迁移及前端生产构建全部通过。

## P06 上传队列可靠性

**目标**：服务重启后自动恢复队列；卡死任务可超时重排；失败任务可重试、取消，并按期限清理暂存文件。

**初步范围**：任务租约、心跳、启动恢复、重试次数、失败原因、管理接口和后台状态提示。

**实施结果（2026-07-31）**：

- 上传任务增加尝试次数、下次重试时间、worker 标识、租约令牌、租约到期时间、心跳、取消请求、错误代码和暂存文件清理时间；SQLite 与 MySQL 共用迁移 `0013_upload_queue_reliability`。
- worker 通过带条件的原子更新领取任务，同一任务只能获得一个有效租约；处理期间按固定间隔续租，旧 worker 即使延迟返回也不能覆盖新 worker 已接管的状态。
- 应用启动时自动恢复没有有效租约的处理中任务；仍有有效租约的任务保持不动，暂存文件已丢失的任务直接记录明确失败原因。
- 可恢复的存储或数据库错误按退避时间自动重试；默认总尝试次数为 3，可在后台设置为 1 至 10 次。失败任务保留暂存文件，管理员可手动重试。
- 后台上传页增加持久任务列表、状态筛选、分页、单项和批量重试、取消及清理。处理中任务采用协作式取消；如果图片已经完整入库，则成功结果优先，避免留下半成品记录。
- 失败任务的暂存文件默认保留 7 天，后台可设置为 1 至 90 天；终态任务历史默认保留 90 天。服务运行时定期清理，启动时也会执行一次维护。
- 系统健康增加目标/存活 worker、排队、处理、等待重试、失败和取消计数。后台设置增加最大尝试次数与失败文件保留天数。
- 新增队列领取、心跳、过期 worker 隔离、启动恢复、退避重试、取消、手动重试、期限清理、分页和批量操作专项测试；P05/P06 专项 14 项、完整后端 114 项测试通过。
- 从空 SQLite 数据库执行全部迁移可到达 `0013_upload_queue_reliability (head)`；前端生产构建通过，后台上传页已在 1280、900 和 390 像素宽度下完成浏览器检查，任务面板无横向溢出。

## P07 图片访问与缓存

**目标**：减少每张图片都经过数据库路径查询和应用层传输造成的开销，同时保持分级、公开状态和权限变更及时生效。

**初步范围**：路径及关联索引、基于图片 ID 的资源地址、缓存头、Nginx 内部转发或 CDN 策略、缓存失效机制。

**实施结果（2026-07-31）**：

- 新增 `/media/{image_id}/{variant}/{media_version}` 资源地址，前台与后台统一按图片 ID、尺寸和访问版本取图，不再为每次展示依赖可变的存储路径；旧 `/storage/{path}` 保留兼容。
- 图片元数据增加 `media_version`。公开状态或分级发生变化时版本自动递增，旧版本地址在源站立即返回 404，前端后续响应自动使用新地址。
- 公开图片返回 `ETag`，浏览器默认缓存 60 秒，共享缓存或 CDN 默认缓存 300 秒；支持条件请求和 304。私有及 `hidden` 图片始终使用 `private, no-store`，并要求后台会话或具有 `library:read` 权限的 API Key。
- 新增原图、预览图、缩略图路径索引，公开图库常用组合索引，以及作品、角色、兼容标签关系表的反向查询索引，兼容 SQLite 与 MySQL。
- 默认继续由 FastAPI 发送图片；可通过 `AGMS_MEDIA_ACCEL_REDIRECT_PREFIX` 启用 Nginx `X-Accel-Redirect` 内部发送，不配置 Nginx 也不影响功能。
- 系统健康现在显示图片发送模式和共享缓存时长；部署文档补充可选 Nginx 配置及 CDN 缓存边界。
- 新增版本匹配、尺寸回退、GET/HEAD、ETag、公开/私有缓存、Key 权限、访问策略变更、旧路径、内部发送和索引专项测试；专项 25 项、完整后端 119 项和前端生产构建均已通过。

## P08 依赖安全与版本锁定

**目标**：升级当前已知存在漏洞的依赖，并让安装、更新与 CI 使用可复现且经过审计的版本集合。

**初步范围**：更新前后端依赖、生成锁定或约束文件、在 CI 中运行安全审计、制定紧急安全升级流程。

**实施结果（2026-08-03）**：

- 后端直接依赖移入 `requirements.in` 与 `requirements-test.in`；运行和测试环境分别由 `requirements.lock.txt`、`requirements-test.lock.txt` 提供完整跨平台版本与 SHA-256 哈希锁。兼容入口 `requirements.txt` 和 `requirements-test.txt` 也会强制使用相应锁文件，旧版更新脚本首次升级到本版本时同样不会绕过哈希校验。
- 修复审计发现的 Python 依赖：`Pillow` 升至 `12.3.0`，`pydantic-settings` 升至 `2.14.2`；安装、升级和新建虚拟环境统一将 `pip` 固定至 `26.2`。
- 前端在既有主版本范围内升级并锁定：`axios 1.19.0`、`vite 6.4.3`、`element-plus 2.14.3`、`vue 3.5.40`，其余前端直接依赖改为精确版本；`package-lock.json` 锁定完整 npm 依赖树。
- 安装器、面板升级、发布包和新备份回滚优先使用 `--require-hashes`。缺少锁文件的历史备份仍可恢复，但会显示明确安全告警；发布打包会强制校验并携带两份锁文件。
- 新增 GitHub 依赖审计工作流：依赖变动、每周定时检查和正式发布均执行 `pip-audit` 与 `npm audit`；Dependabot 每周检查 Python、npm 和 GitHub Actions 更新。
- 新增 [依赖安全维护](dependency-security_zh.md)，定义锁文件再生成、合并前检查和紧急安全补丁流程；英文版位于 `dependency-security.md`。
- 验证通过：带哈希的全新运行/测试环境安装、`pip check`、`pip-audit`（无已知漏洞）、`npm audit`（0 漏洞）、后端完整 121 项测试、前端生产构建、安装/升级脚本语法、发布包生成及升级脚本干跑。发布包已核验包含锁文件，未包含真实 `.env`、数据库或图片数据。

## P09 数据库并发策略

**目标**：SQLite 默认采用保守并发并启用适合的并发参数，MySQL 则按服务器资源提供高吞吐配置。

**初步范围**：SQLite WAL、忙等待和 worker 上限；MySQL 连接池与 worker 参数；设置页提示及压力测试。

**实施结果（2026-08-03）**：

- 文件型 SQLite 连接会自动启用 WAL、外键检查、可配置忙等待和 WAL checkpoint；默认使用 8 秒等待与 `NORMAL` 同步策略。上传队列的实际 worker 数在启动前会被限制为最多 4 个，避免多个写事务持续争抢锁。
- MySQL/MariaDB 使用可配置的预检连接池、连接回收、连接与读写超时及 LIFO 空闲连接复用。默认提供 24 个常驻连接和 40 个溢出连接，并保留 4 个连接给网页请求，因此上传 worker 的默认可用上限为 60。
- MySQL 8 领取上传任务时使用 `FOR UPDATE SKIP LOCKED`；SQLite、MariaDB 和旧版 MySQL 保留带条件的原子更新兜底。短暂锁竞争会回滚后等待下一轮领取，单个 worker 不会因此退出。
- 新增迁移 `0015_database_concurrency`，只为上传任务增加按领取条件排序的复合索引，不改写既有图片、关系或任务数据。
- 后台设置会按当前数据库显示并限制可填写的 worker 上限；系统健康会展示 SQLite WAL/忙等待或 MySQL 连接池占用情况。
- 已加入 SQLite WAL、MySQL 连接池、worker 上限、`SKIP LOCKED` 语句和并发领取唯一性的专项测试。7 项 P09 专项测试和完整后端 128 项测试均已通过，前端生产构建与 API 文档生成通过。
- 本地既有 SQLite 数据库已从 `0014_media_delivery_cache` 升级至 `0015_database_concurrency`；实际确认领取索引存在、`journal_mode=wal`、`busy_timeout=8000`，新版本地预览服务健康检查正常。
- MySQL 参数与 `SKIP LOCKED` 已使用 SQLAlchemy MySQL 方言和连接池单元测试验证；真实 MySQL 服务的集成测试及压力测试纳入 P10 上线保障体系。

## P10 上线保障体系

**目标**：代码合并前自动验证 SQLite、MySQL、前端构建和关键用户流程，并建立可恢复的数据库与图片备份机制。

**初步范围**：push/PR CI、MySQL 测试服务、Playwright 冒烟测试、定期备份与恢复演练、前端路由按需加载。

**已批准实施计划（2026-08-04）**：

1. 新增常规 push / PR 验证工作流，分别运行 SQLite 全量后端测试、真实 MySQL 8 迁移与并发领取测试、前端构建和浏览器端到端流程。
2. 在发布工作流中加入独立 MySQL 8 验证门槛，避免仅在 SQLite 通过后就发布包含数据库兼容性问题的版本。
3. 新增定期备份入口，按保留天数清理旧备份；常规备份同时覆盖数据库、原图、缩略图和 HDR 的 SDR 预览图，并由自动化恢复演练验证 SQLite 与 MySQL 路径。

5. 保持首页首屏组件同步加载，将其余公开页和后台页改为路由级按需加载；首页空闲后分批预热常用公开页面，并在导航悬停或聚焦时提前加载目标页面。

**实施结果（2026-08-04）**：

- 新增 `Verify` 工作流，覆盖任意分支推送、Pull Request 和每周计划任务；其中分别验证 SQLite 全量后端测试、真实 MySQL 8 的迁移与并发任务领取、前端构建，以及 Chromium 的桌面和手机端关键流程。
- 发布工作流新增独立的 MySQL 8 验证门槛；MySQL 与 SQLite 任务都会执行完整的备份恢复演练，失败时浏览器测试会保留追踪、截图、视频和 HTML 报告。
- 新增 `scripts/backup_gallery.sh`。它在 `backups/scheduled/` 内创建受保留天数控制的完整备份，覆盖数据库、原图、缩略图和预览图；恢复脚本能够恢复这些持久媒体目录，并在缺少 `rsync` 的环境下使用受同一排除规则约束的 Python 后备同步。
- 本机已实际通过 SQLite 备份、过期备份清理和恢复演练；演练使用独立临时目录，不会读取或改写现有图库。完整后端回归 `132` 项通过（`2` 项 MySQL 测试在本机无 MySQL 服务时按设计跳过）。
- Playwright 的 Chromium 桌面/手机流程已实际通过：首页到图片库导航、管理员登录、系统设置、图片选择预览、提交上传任务，以及手机横向溢出检查。测试数据库和存储目录与本地运行数据隔离。
- 首页继续作为同步首屏，其他公开页、登录/安装页和后台页改为路由级加载；首页空闲后按顺序预热常用公开页，导航悬停或聚焦会立即预热目标页。生产构建已确认生成独立页面块。
- 本机没有 MySQL 服务，因此不模拟或连接生产数据库。下一次推送或 Pull Request 会在 GitHub Actions 的独立 MySQL 8 服务中执行真实迁移、并发领取及 MySQL 备份恢复演练。
