# 维护发布约定

本文件记录项目维护者确认的默认发布流程。

## 触发语句

维护者说“推 GitHub”时，默认含义是发布当前已验证的项目版本，而不只是推送一个普通提交。除非维护者明确说明“仅提交”“仅推送分支”或“不要部署”，应完成以下整个流程。

## 默认流程

1. 核对改动范围，排除与项目无关的未跟踪文件、密钥、数据库、存储和备份。
2. 更新与本次改动有关的项目文档、示例配置和测试；运行相应的构建与测试。
3. 创建清晰的 Git 提交。未指定版本号时，基于最新标签递增补丁版本，例如 `v0.3.7` 之后默认使用 `v0.3.8`。
4. 创建对应的带注释 Git 标签，并推送 `main` 与该标签至 GitHub。
5. 将同一提交的运行时代码部署到云端；部署前保留可恢复备份，且不修改 `.env`、数据库、图片存储或备份，除非本次改动明确要求。
6. 执行云端健康检查；涉及静态资源或媒体缓存时，还应核对实际响应头与 CDN 缓存状态。
7. 汇报提交、标签、GitHub 推送、云端部署、验证结果及任何未包含的用户文件。

## 媒体缓存发布要求

公开图片使用版本化 `/media/{image_id}/{variant}/{media_version}` 地址。任何替换原图、预览图或缩略图内容的维护操作都必须递增 `media_version`，确保长时间浏览器/CDN 缓存不会阻挡后台刷新后的新图。私有、隐藏及带 `share=` 授权的图片必须继续绕过共享缓存。

## 前端首屏验收

首屏包含异步图片、缩略图或数据列表时，容器、边框、翻页与操作控件应在首帧稳定渲染；不得以图片数量或加载完成状态作为是否插入这些界面结构的条件。图片内容可以逐项补齐，但控件不应在加载后突然出现、移动或造成页面割裂感。

## 覆盖方式

维护者可以在单次请求中明确指定版本标签、仅推送 GitHub、仅部署云端、跳过标签或跳过某项验证；该次明确指令优先于本约定。
